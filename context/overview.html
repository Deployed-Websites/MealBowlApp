Project Overview

MealBowlApp — Jyoti's Superbowls

A small ordering site where customers browse a fixed menu of healthy meal bowls, see ingredients and macros, and build up a running order that an admin can review across all customers.

Since the last major change Current

This is the first documentation pass for this project — there is no newer activity yet to report beyond it.

  • This overview, along with a matching technical handoff document, was written for the first time by reviewing the whole project from scratch — the code, the way the two halves of the app talk to each other, and the history of changes made to it so far. Nothing in the app itself changed as part of this pass; this is purely a documentation exercise so that future work has a clear starting point.
  • While reviewing the project, a few loose ends were noticed and are worth flagging honestly rather than glossing over: a page that shows every customer's orders currently only shows whatever was last saved to the visitor's own browser rather than always fetching the newest information, and the ordering system does not double-check that the price a customer's browser reports for an order matches the real menu price. Neither of these has been fixed yet — they're just written down here so they aren't forgotten. See the "Known rough edges" section below for the complete list.

Major change: original build Past

The app as it stood before this documentation pass — everything built up to now.

  • The core idea of the site was built: a public page listing a small menu of pre-made healthy meal bowls, a details page for each bowl showing its ingredients and nutrition breakdown, an account system so customers can register and log in, a running order/basket that customers can add to and adjust, and a checkout-style page to review that basket. No real payment step was ever added — checkout simply keeps track of what someone has ordered and what it adds up to.
  • A separate page was added for an administrator to see every customer's orders and totals in one place, so whoever runs the business can keep track of what's been requested without payment processing being involved.
  • Midway through building the site, a round of housekeeping was done: pieces of login and syncing logic that had been copied into several different pages were pulled out into shared, reusable pieces, files were reorganized into clearer folders, and all the communication with the server was consolidated into one place instead of being scattered across the app. This was a cleanup effort, not a change in what the app does for customers.
  • Separately, and unrelated to the meal bowl site itself, some personal file-organizing tools and notes ended up committed into the same project storage. They don't affect how the site works for customers, but they are flagged in the technical documentation as things that probably belong in their own, separate project.

Known rough edges

Provisional or unfinished areas a future contributor should know about before trusting or refactoring them.

Admin page shows stale data. It only displays whatever was last saved to the visitor's own browser and never asks the server for a fresh copy on its own.
Order prices aren't double-checked. The server currently trusts whatever price the customer's browser reports for an order rather than verifying it against the real menu.
Leftover unused code. An old login-helper file appears to have been fully replaced by newer shared code but was never removed.
A sign-out edge case was intentionally left simplified rather than fully polished, with a note left in the code to revisit it later.
The app leans heavily on the browser's own temporary storage to remember login state and cached data, rather than a more robust approach — this is the root cause of the stale admin page issue above.
Diagnostic messages are still being printed during normal use in a few places, left over from development.
No automated tests exist for either half of the app, though the tooling to run them is present.
A sign-in setup for a different service was configured early on but never actually used — the app authenticates a different way instead.
Unrelated personal files and tools (a spreadsheet-combining utility, generated sample files, and personal notes) are stored in the same project as the meal bowl site and should probably live somewhere separate.
